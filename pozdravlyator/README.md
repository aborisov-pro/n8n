# 🎉 Поздравлятор — поздравление в MAX

> Вебхук-бот: получает сообщение из MAX, генерирует короткое персональное поздравление с юмором и отправляет ответ в тот же чат.

---

## Что делает

Поздравлятор принимает входящее сообщение пользователя (кого поздравить, повод, детали) через вебхук и превращает его в короткий текст «как на открытке».

Он извлекает контекст из запроса, избегает банальных формулировок и генерирует 3–4 предложения с лёгкой иронией и 1–2 эмодзи по смыслу.

После генерации бот отправляет сообщение обратно в MAX. Дополнительно воркфлоу может писать технический лог в централизованный логгер «Писец».

---

## Архитектура

```
MAX → Webhook (POST)
  → AI Agent (LLM)
  → Отправить в MAX
  → Set LOG
  → LOG через Писец
```

## Узлы (6 нод)

| Нода | Тип | Назначение |
|------|-----|-----------|
| Webhook | Webhook | Приём POST от MAX |
| AI Agent | LangChain Agent | Извлечение контекста и генерация текста поздравления |
| OpenAI Chat Model | LLM | Языковая модель для агента |
| Отправить в MAX | HTTP Request | Отправка ответа обратно в чат |
| Set LOG | Set | Формирование объекта лога (имя воркфлоу, execution id, статус, фрагмент ответа) |
| LOG через Писец | Execute Workflow | Асинхронная отправка лога в «Писец» |

---

## Логика ИИ

Агент получает исходный текст пользователя, имя отправителя и текущую дату. На основе этого он:

▪ извлекает из сообщения повод, роли и детали (профессия, увлечения, характер, отношения)  
▪ выбирает имя именинника из сообщения, а если его нет — берёт имя отправителя  
▪ если повод не указан — подбирает ближайший подходящий по текущей дате  

Выход всегда «без служебных слов»: только текст поздравления, 3–4 предложения, без штампов вроде «счастья и здоровья».

---

## Особенности реализации

▪ **Короткий формат** — агент ограничен 3–4 предложениями «как на открытке».
▪ **Запрет клише** — банальные поздравительные формулы явно запрещены в системном сообщении.
▪ **Ответ в тот же чат** — `chat_id` берётся из входящего webhook payload.
▪ **Устойчивость к сбоям API** — нода отправки в MAX работает с `onError: continueRegularOutput`.
▪ **Асинхронный лог** — «Писец» вызывается с `waitForSubWorkflow: false`, чтобы не задерживать ответ пользователю.

## Зависимость: Писец

Этот воркфлоу использует **[Писец](../pisec/)** — централизованный логгер.

| Вход Писца | Что происходит |
|------------|----------------|
| `Execute Workflow Trigger` | Штатный лог → Supabase |
| `Error Trigger` | Перехват ошибок → Supabase + Телеграм-алерт |

> ⚠️ Импортируй и активируй Писца первым.

## Порядок установки

1. Импортировать и активировать **Писца**
2. Импортировать: **Settings → Import workflow → `Pozdravlyator_Generate_Greeting.json`**
3. Настроить credentials: **OpenAI API**, **HTTP Header Auth**
4. Заменить плейсхолдер `YOUR_PISEC_WORKFLOW_ID` в ноде **LOG через Писец**
5. Зарегистрировать вебхук в MAX: `https://<твой-домен>/webhook/max-pozdravlyator`
6. Активировать воркфлоу
